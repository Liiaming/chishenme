# 部署说明

## 构建与预览

构建环境使用 Node.js 24.x 和 npm 11：

```bash
npm ci
npm run build
npm start
```

`out/` 是完整静态站点，`npm start` 仅用于本地预览。构建完成后不需要 Node.js 生产进程。

## 静态托管

在 Vercel 或其他静态托管平台中，使用以下配置：

| 设置 | 值 |
| --- | --- |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 发布目录 | `out` |
| Node.js | `24.x` |
| 环境变量 | 无 |

也可以将本地构建的 `out/` 内容上传到静态服务器。现有配置面向域名根路径；部署到 `/chishenme/` 等子路径时，需要另行配置资源路径并验证，不能直接照搬根路径产物。

生产站点使用 HTTPS。菜单保存依赖浏览器 Web Locks；普通远程 HTTP 地址无法满足安全上下文要求时，应用会提示无法保存。不要直接双击 `out/index.html` 通过 `file://` 使用。

## 菜单存储

菜单仅保存在当前站点、当前浏览器的 `localStorage` 中，不上传至服务器。域名、协议、端口或浏览器变化后，原菜单不会自动迁移；清理站点数据也会删除菜单。

多标签页会同步菜单变化。读取失败或数据损坏时，应用使用默认菜单并提示；保存失败时保留旧菜单和输入。编辑窗口中的“重置菜单”会以默认菜单替换现有菜单，操作前需要确认。

修改代码中的默认菜单只影响没有保存过菜单的浏览器，以及主动重置菜单的用户，不会覆盖已有自定义内容。

## 浏览器验证

请使用支持 Web Locks、现代 CSS 和本地存储的浏览器版本。自动化目前覆盖 Chromium 桌面和移动视口；Safari、Firefox、真实手机和软键盘需要额外验证，不将模拟测试视为这些环境的兼容保证。

部署后检查首页、图标和静态资源能否加载，再检查添加菜单、刷新保留、多标签页同步与重置操作。部署者自行添加的分析脚本或服务不属于本项目默认行为。
