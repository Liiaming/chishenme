# 依赖升级与纯前端修复

## 已批准的目标与约束

- 升级 Next.js、React、现有 shadcn/Radix 组件及其他依赖，使用 npm 和 package-lock.json。
- Next.js 配置 `output: "export"`，构建输出 out/；部署仅托管静态文件，不运行 Next.js 服务。
- 不添加 API 路由、Server Actions、数据库、账户或网络数据服务。菜单继续仅存在当前浏览器。
- 尽量保持现有外观和开始/结束、新增/删除/重置菜单的功能，不新增重命名等功能。
- 不提交 Git；用户仅授权实现和验证。

## 方案取舍

采用完整迁移到 Next.js 16、React 19、Tailwind 4 并更新本地 shadcn 组件源码。仅修补旧 Next.js 14 无法获得受支持的基础栈；重建应用或改用其他框架则超出范围。

保留 Radix 底层和现有主题，使用官方 CLI 对比并更新组件。旧 default 样式已弃用，采用官方 new-york 样式以获得 React 19/Tailwind 4 实现，不引入新视觉预设。

实现者核实的兼容性限制：TypeScript 7 超出当前 typescript-eslint 的支持范围，使用 6.0.3；React ESLint 插件尚未声明支持 ESLint 10，使用 9.39.5。Node.js 使用 24.x，类型声明采用对应主版本的最新补丁。

## 数据与交互

- 读取本地存储时校验 JSON 与字符串数组，处理存储不可访问和损坏数据，使用默认菜单并显示可恢复提示。
- 修改菜单先保存成功再发布界面更新；保存失败保留旧菜单和用户输入，显示错误。
- 使用浏览器 Web Locks 串行化跨标签页的读改写，监听 storage 事件同步数据；生产部署要求 HTTPS（本地 localhost 可用）。
- 抽选只使用当前内存菜单，不在定时器中读取存储；空菜单禁止开始，随机下标正确覆盖 0。
- 背景不接收点击、对辅助技术隐藏、限制溢出，并尊重减少动态效果的系统设置。
- 已有菜名使用文本展示；新增表单有标签和空白校验；图标按钮具备名称，结果对比度达标，页面语言为中文。

## 验证

依次验证 npm 干净安装与依赖树、lint、类型检查、逻辑测试、生产静态导出、安全扫描，以及基于静态文件服务器的 Playwright 回归。

浏览器回归覆盖默认菜单、持久化、空菜单、存储损坏/禁用/容量不足、停止按钮命中、跨标签页顺序与并发更新、可访问名称和移动端布局。新版 Tailwind 的最低浏览器要求：Chrome/Edge 111、Safari 16.4、Firefox 128。
