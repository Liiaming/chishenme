# 吃什么：蓝白菜单字场

日期：2026-11-12
版本：第二版，替代此前“开饭现场”草案
状态：用户已确认并完成实现；实际验证与限制见第 12 节。未新增依赖，未执行 Git 提交。

研究依据：[GitHub 源文件参考与取舍](./2026-11-12-visual-design-research.md)。本版基于 4 个仓库中 17 个完整阅读文件及一个定向阅读章节，不再停留在 skills.sh 的条目介绍。

## 1. 重新定义问题

这个应用不是“尽快返回一个随机字符串”的工具，也不是需要观看开奖表演的游戏。它提供一个很小但完整的体验：犹豫 → 热闹地选一会儿 → 亲手停下 → 获得一个清楚的答案。

用户已经明确：固定排布、缓慢平移很无趣，希望有随机感，并要求重新设计整体体验。其他视觉选择由本方案提出，用户随后以“按你的建议修改”确认了本方向。

### 旧草案应当推翻什么

- “浅底、大字、黄色按钮”缺少足够具体的视觉身份。
- 随机背景被写成弱化的装饰，仍可能在优化时被删掉或磨平。
- 给了更新时间和数量，却没有完整设计待机、运行、停止的衔接。
- 菜单管理只是弹窗换肤，没有解决桌面和手机的不同操作位置。

### 本版主张

**让真实菜名组成画面。待机是一张安静的菜单字场，运行是错拍的随机跳切，停止是一次立即收住的点单。**

它应当热闹、有食欲、直接，不故作高级，不使用办公软件的卡片体系，也不堆转盘、食物照片或表情图标。

## 2. 方向与取舍

| 方向 | 核心体验 | 结论 |
| --- | --- | --- |
| 菜单字场 | 不同尺度的真实菜名组成画面，开始后快切、跳位，中心答案清楚稳定 | 推荐，随机感直接，也能使用任意长度和数量的现有菜单 |
| 翻页点菜单 | 中央像翻动菜单一样逐项切换，外围相对安静 | 有秩序，但随机感集中在中央，容易再次显得规整和机械 |
| 转盘/老虎机 | 通过指针、转轮或滚筒体现选择 | 具象，但默认 43 项不适合在小屏转盘上阅读，也容易把重点变成等待动画 |

推荐第一种不是把其他方案说成不能实现，而是它更符合用户刚刚指出的问题，并且不需要引入新玩法。

## 3. 视觉身份：蓝白菜单，点单红

取餐饮环境中蓝白菜单和醒目点单记号的语言，但不模拟旧纸、油污、搪瓷纹理或复古招牌。

### 3.1 色彩与用途

| 角色 | 浅色值 | 用途 |
| --- | --- | --- |
| 页面底色 | #F7F8FC | 干净、偏冷的白底 |
| 面板底色 | #FFFFFF | 菜单、输入与确认区域 |
| 正文 | #202631 | 可操作内容与说明 |
| 菜单蓝 | #27469B | 主标题、结果、菜单字场的共同身份 |
| 点单红 | #C63B24 | 唯一主按钮，不铺成大面积背景 |
| 次要文字 | #596579 | 数量、持久化说明与辅助信息 |

边界使用 #D4DAE4；错误使用 #A52C22，并搭配明确错误文字，不只靠红色传达失败。实际 CSS 复用现有语义变量，不另外搭 token 生成系统。

基础不透明色对已经用 WCAG 相对亮度公式计算：正文/底色 14.31:1、菜单蓝/底色 8.12:1、次要文字/底色 5.55:1、白字/点单红 5.18:1、错误红/白色 7.04:1。这不是浏览器最终合成色、所有交互状态或完整可访问性认证。

保留现有深色样式兼容，不新增主题切换功能。深色映射：底色 #141C2B、面板 #202A3A、正文 #F5F7FC、菜单蓝 #91AFF3、主按钮 #FF9580 配深色文字、次要文字 #AAB8D0、错误 #FFB4A8。对应基础文字色对也已计算，实际渲染仍需复核。

### 3.2 字体、形状与密度

- 中文黑体承担主视觉，优先使用本机 PingFang SC、Microsoft YaHei 等回退；不借一个只覆盖拉丁字符的新字体假装重做中文排版。
- 主字使用粗字重，手机约 44–56px、桌面约 64–104px；正文 16px；辅助信息 14px。具体断行按真实菜名校准。
- 主视觉不做“一个字换颜色”的装饰，整个问题或结果作为一个完整文字形态。
- 外围菜名分少量固定尺度层级，而不是每帧改变字号。大字可贴近画面边缘，中心内容完整可读。
- 不再依赖 blur 制造层次：靠字号、疏密、色彩深浅和前后位置区分。
- 只为操作和浮层提供容器。背景菜名不套卡片、不变成一堆胶囊标签。
- 主按钮适度圆角，约 56px 高；其他操作触摸目标至少 44×44px，图形可以小于命中区。

## 4. 三个状态是一张画面的变化

左上角保留轻量站点名称；右上角使用有文字的“菜单”，旁边按空间显示实际数量。不增加首页介绍区、统计卡、宣传标语或教程。

以下为文字分镜，不是假称已经生成的页面截图。

### A. 待机：一张有内容的菜单

```text
吃什么                                      菜单 43

        馄饨                        烤肉

                     今天
                    吃什么？

              [ 开始选 ]

    酸菜鱼                          重庆小面
```

- 少量真实菜单文字静置在外围，让首次打开就知道这是关于吃饭的应用，而不是空白通用工具。
- 此时没有自动漂移、循环呼吸、按钮摇晃或入场排队。
- 中央大字既是问题也是视觉主体，不再叠加第二条同义标题。
- 字场不是新的可点击菜品列表，不让用户误以为点击背景能指定结果。

### B. 运行：画面打散，操作不动

```text
吃什么                                      菜单 43

          火锅              炒饭

                    正在选

                   酸菜鱼

            [ 停，就吃这个 ]

    烤肉                             饺子
```

- 中央候选菜名是视觉主角，外围字场提供随机变化的现场感。
- 主按钮、菜单入口和中央舞台占位固定。只有文字和字场更新，不让整个页面随内容跳动。
- 当前菜名快速换，但不为每个候选播放完整的飞入飞出或滚筒动画；页面语义主标题保持稳定，不把动态候选当成持续改写的主标题。

### C. 落定：先有答案，再有强调

```text
吃什么                                      菜单 43

                    选好了

                   酸菜鱼

              [ 再选一次 ]
```

- 停止时锁定当前候选，不为了“减速”再抽几道菜。
- 结果立即成为完整可读内容，外围文字快速退出，留下清楚的答案。
- 蓝色结果下可以出现一次很短的红色落定线，表示确认；不是印章贴纸，不出现庆祝文案、彩纸和音效。
- 再选一次直接开始新的选择，不重播首次进入效果。

## 5. 随机的设计规则

### 5.1 随机什么，固定什么

| 随机 | 固定 |
| --- | --- |
| 外围菜名出现的位置、替换顺序、驻留时长 | 中央阅读范围、主操作位置、菜单入口 |
| 菜名分配到哪一尺度层级 | 有限的字号层级和主色，不随机 RGB |
| 局部替换的时间错位 | 屏幕同时存在的数量上限 |
| 每次开始重新生成的组合 | 结果从现有完整菜单中等概率选取 |

背景不允许改写抽签候选数组、增加某道菜的权重或替代实际结果。动效的数据职责与抽签分开，但不为此新增一套随机算法框架。

### 5.2 快切，而不是慢飘

以下是首轮视觉验证的起始范围，不是已经调好的最终效果：

- 普通桌面运行时约 12–18 个外围菜名，手机约 6–9 个；待机数量约为运行的一半。数量预算包含尚未退出的副本，避免过渡期悄悄翻倍。
- 菜单少于所需数量时直接减少，不复制同一个菜名来伪造丰富度；空菜单不生成字场。
- 每约 160–280ms 触发一小批更新，一次改变约 2–4 个，不能整屏同拍闪烁。
- 驻留长短有差异，通常约 0.6–1.6s，并与当前节点数和替换批量一起校准；新出现位置不只是前一个位置附近的一点偏移。
- 主要动作是换到新位置，辅以约 8–20px、100–160ms 的短促滑入；不沿长路线穿越中央区域，不做 6 秒慢漂移。
- 尺度和色彩深浅分层，方向和时序错开。避免固定网格被肉眼认出来，也避免字群都堆到一个角落。
- 大面积亮暗反转、同步闪白、持续旋转和满屏抖动均不是本方案的随机感。

实现只需要有限空间分区和局部错拍，不做持续碰撞检测、粒子物理、复杂噪声场或用户可调参数面板。

### 5.3 空间约束

- 中央问题、结果与按钮外留出明确的阅读安全区；菜单入口也有避让空间。
- 采用几块宽松外围区域，在区域内随机，不能按菜品索引固定成同一布局。
- 菜名过长时仅装饰副本可截断，真实菜单与最终结果不丢失原文。
- 窄屏或低高度优先减少装饰，不压缩主按钮、不减小结果至难读，也不横向撑破页面。
- 背景不可接收点击，对辅助技术隐藏。它提供趣味，不制造第二套选择方式。

## 6. 动效编排：哪些动，哪些不动

| 事件/元素 | 起点 | 草案时长 | 关系与目的 |
| --- | --- | --- | --- |
| 主按钮按压反馈 | 指针按下 | 80–120ms | 轻微压下；业务操作仍使用正常按钮激活，不把 pointerdown 当成唯一入口 |
| 开始选择 | 按钮激活 | 立即 | 中央候选和外围更新同时开始，不等开场 |
| 中央候选 | 运行中 | 初始按 60–90ms 换词验证 | 直接替换文本，无每字逐项动画；最终节奏看实际运行效果 |
| 外围字场 | 运行中 | 见局部节奏 | 与中央不同拍，不形成整屏同步闪动 |
| 锁定最终结果 | 停止激活 | 立即 | 停止抽样，不等待任何退出或强调动画 |
| 外围退出 | 同一停止事件 | 100–160ms | 停止位置更新，淡出；不飞向中心、不回收排队 |
| 结果落定线 | 同一停止事件 | 140–180ms | 与外围退出并行，一次性强调 |
| 菜单面板 | 打开/关闭 | 进入约 180ms、退出约 120ms | 面板作为整体出现，菜单行不逐条入场；内容立即可操作 |

刻意不动：站点名称、菜单入口、按钮位置、输入文字、菜单行、菜品数量和错误内容。菜单增加/删除不播放庆祝，不为极短保存显示一闪即逝的加载骨架。

重复开始、连续快速停止、退出尚未结束时重新开始、打开菜单、外部菜单变化都必须可打断旧过程。动画不能反过来控制业务状态或重新恢复已经停止的抽签。

系统开启减少动态效果时：不显示外围字场，不做位移、缩放和落定线；中央候选改为约 500ms 的低频文本更新，仍可主动开始、停止和读取结果。抽签中不连续语音播报，仅停止后播报最终结果。

## 7. 手机不是桌面的缩略图

- 手机中央结果使用更大的画面占比；外围字场更少，避免挤出一屏。
- 主按钮有独立布局区域，不根据菜名高度重新定位。候选阶段最多两行，超出临时省略；停止后完整显示。
- 普通长菜名可在结果区换行；极长结果的全文区域可滚动且能获得键盘焦点，不用仅 hover 才能看到的 tooltip 交代全文。
- 普通高度力争一屏完成操作，但 320px 窄屏、横屏、软键盘或 200% 放大时允许合理滚动，不能裁掉内容来维持一屏。
- 使用稳定小视口作为首页基准，面板按当前可用高度适配；考虑顶部与底部安全区。
- 输入维持至少 16px；保留缩放能力；只有支持 hover 的设备得到 hover 反馈，触屏仍有按压反馈。
- 按钮文字不参与长按选中，结果、菜单文字和错误内容可以选择复制。

## 8. 菜单：桌面侧边，手机底部

同一套现有 Radix/shadcn Dialog 语义与焦点管理，通过布局适配，不新增 Drawer 库，不新增拖拽关闭、弹簧物理和滑动手势。

### 桌面

右侧约 380–420px 的菜单面板，和右上角入口建立位置关系。首页退为背景，不继续随机运动。

### 手机

底部展开的菜单面板，最大约占可用高度的 85%–90%，低高度和键盘出现时以可达性为先。提供明确关闭按钮；不能只靠下滑关闭。

```text
我的菜单 43                                关闭
只保存在当前浏览器

新增菜品
[ 例如：酸菜鱼…                  ] [ 添加 ]
（输入或保存失败时，错误放在这里）

馄饨                                   删除
酸菜鱼                                 删除
重庆招牌酸菜肥牛米线套餐                  删除
……独立滚动……

重置菜单
```

- 输入放在列表前面，不需要先滑过 43 道菜才能添加；成功保存才清空，焦点留在输入框。
- 菜名是可换行的文本，不伪装成可编辑输入；删除目标固定尺寸，不被长菜名挤掉。
- 保存中不禁用并丢失输入焦点，但禁止重复提交和冲突操作；长时间等待才使用不改变尺寸的保存状态。
- 保存失败保留草稿和旧列表，就近说明“修改尚未保存”；不播放成功反馈。
- 菜单关闭后焦点回入口，不自动恢复抽签。
- 重置进入同一面板内的明确确认状态，说明将替换当前菜单，提供“保留菜单”和“确认重置”；不叠加另一层复杂管理界面。
- 维持现有单项删除语义；重置才需要额外确认，不新增撤销、排序、改名、搜索或分类系统。

## 9. 组件与异常状态

| 对象 | 正常 | 交互中/失败/空状态 |
| --- | --- | --- |
| 主按钮 | 红底白字、足够大、文案直接 | hover 清楚反馈、按压轻微下移、键盘焦点清楚；不能凭动画完成事件才允许点击 |
| 菜单入口 | 文字入口，数量次要 | focus 可见、计数变化不改变控件高度 |
| 新增输入 | 有可见标签，16px 输入字 | 错误与控件关联，保存中保持焦点，失败保留值 |
| 菜品行 | 完整菜名、固定删除目标 | 单项/长名/多行仍能操作，不因删除动画推迟保存或触发重复删除 |
| 空菜单 | 明确“菜单还是空的” | 唯一主操作变为“添加菜品”，直接打开菜单；没有假随机或无响应按钮 |
| 读取损坏/权限失败 | 默认菜单仍可抽签 | 提供当前浏览器无法读取菜单的说明和菜单入口，不能静默把坏数据当成功保存 |
| 保存失败 | 旧菜单仍是真实状态 | 明确未保存及重试/重置途径，不用短暂 toast 代替持久错误 |
| 外部菜单更新 | 继续使用现有同步能力 | 停止当前抽签；已删菜品清空结果，仍存在的结果可保留 |

首页的存储警告使用正常布局中的提示区，不覆盖舞台和按钮；菜单内的保存错误就近显示。错误说明可以谈浏览器权限和 HTTPS，不用俏皮话掩盖问题。

## 10. 实现边界与性能预算

- 继续纯前端与 Next.js 静态导出，发布 out/；不新增 API、Server Actions、账户、数据库或 Node.js 生产服务。
- 保持存储键 foods、现有校验、save-before-publish、Web Locks 与跨标签页同步。视觉改造不迁移或清空数据。
- 继续使用现有 Radix/shadcn 与 Tailwind；不安装远程 skills、Motion、GSAP、p5.js 或字体依赖。
- 复用语义主题变量，不另建品牌生成器、组件框架或多层 token 工程。
- 随机值在事件和局部更新阶段生成，不放入 React 渲染过程，不重新轮询 localStorage。
- 连续运动交给有限的 transform/opacity 过渡；不能为了背景每帧重渲染整个页面，也不能默认 transform 就一定流畅。
- 装饰节点数量不跟菜单总数无限增长；长菜单的保存与完整读取行为不因装饰数量上限改变。
- 页面不可见时暂停装饰更新；停止、开菜单、重入和卸载清理旧计时/动画，回到页面不能自行恢复已停止状态。
- 以真实中端手机录屏/性能记录验证，而不是承诺未经测量的帧率；桌面 CPU 节流只能作为辅助。

## 11. 验证清单与尚未验证事项

### 保留既有保护

现有存储损坏、权限/配额错误、Web Locks 不可用、多标签页并发、空菜单、删除后重加、状态清理、持续输入、长菜名、按钮命中和对比度测试继续覆盖。调整文案与布局时同步更新断言，不以删除测试换取通过。

### 新版专属验收

- 用录像确认：待机静止 → 开始同时响应 → 运行错拍跳切 → 停止立即锁定与并行退出，确实不是固定轨迹慢漂移。

### 设计自检后的取舍

- 没有为了“更有趣”增加轮盘、音效、贴纸和按钮表演；记忆点只在菜名字场。
- 没有把算法艺术资料的“可控随机”扩张成噪声场、物理引擎或用户参数面板。
- 没有把手机原生资料的手势建议扩张成新的拖拽交互。
- 没有将大字号当成完整设计：三种状态、固定操作位置、有限随机维度、菜单工作流与边界数据都已有约束。

### 实现结果

- 首页使用蓝白字场与红色操作；开始后候选约 80ms 切换，外围每 160–280ms 随机更新一批菜名与位置。停止立即锁定，不为退出动画重新抽样。
- 外围按安全区域分配有限位置，再随机取位；桌面最多 18 个节点、手机最多 9 个，待机约减半。普通短菜名适配字号，长菜名装饰副本才允许省略，真实结果与菜单保留完整文本。
- 菜单复用 Radix Dialog，桌面右侧、手机底部；添加放在独立滚动列表前，重置在同一面板内确认，取消与关闭恢复焦点。
